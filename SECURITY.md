# Security and privacy notes

Report vulnerabilities privately to the project owner with the smallest reproducible example possible. Do not include API keys, interview transcripts, screenshots, raw audio, exports, or other personal information in a report.

## Offline translation packs

Offline translation uses official Argos data archives from a fixed application catalog. The renderer supplies only an allowlisted target language, never a download URL, filesystem path, executable, or model configuration. Trusted IPC owns download, cancel, and removal. Downloads have fixed byte limits and publisher ETag/MD5 integrity checks over HTTPS; this archive checksum is not a cryptographic signature. ZIP extraction rejects traversal, absolute paths, Windows path syntax, and symlinks, bounds entry count and expanded size, and writes only known data and attribution files to staging. Scripts and unused Stanza assets are never installed. Cancellation and failure clean staging. Installed files have recorded SHA-256 hashes, checked before model loading and rechecked when file metadata changes. Local filesystem modification is outside the authenticity boundary.

Inference uses the pinned CTranslate2 native addon in an Electron utility process with CPU-only execution, no networking code, and no credentials. The worker divides bounded caption text into short passages. The main process serializes inference requests and keeps one model loaded. Abort, language changes, caption stop, pack removal, and application quit terminate inference. Missing packs and local failures never trigger a hosted fallback. The source language is explicitly English in this version.

## Renderer trust boundary

The renderer is untrusted. It runs with Node.js integration disabled, context isolation enabled, Chromium sandboxing enabled, and web security enabled. Privileged operations are available only through the allowlisted preload bridge.

Every privileged IPC handler verifies that the sender:

- is the web contents owned by the application's main `BrowserWindow`;
- is that web contents' main frame; and
- has the expected renderer URL.

For packaged builds, the trusted URL is the exact local renderer `index.html` file; query strings and fragments do not permit a different file. For development, `ELECTRON_RENDERER_URL` must use HTTP on a loopback host, and the trusted sender must match that configured origin and pathname. Arbitrary loopback pages are not trusted merely because they use localhost.

Top-level navigation outside the trusted renderer is blocked, webview attachment is blocked, and new application windows are denied. Only approved OpenAI documentation links may be handed to the operating system for external opening.

Because API keys and HTTP proxy credentials are entered in the renderer, a renderer compromise could observe them during entry. After submission, saved secrets stay in the main process and are never returned to the renderer. The renderer receives public connection status and owner-bound caption session IDs. Legacy Realtime endpoints also return short-lived credentials for an approved microphone session.

## Main-enforced consent grants

The visible React confirmation is a user-facing disclosure, not the sole enforcement boundary. The main process displays native confirmation dialogs and issues random, expiring grants bound to the requesting renderer's web-contents ID.

- **Live session:** valid for up to four hours and checked by the main process on every Live-mode coaching request. The renderer releases it when the session ends or resets.
- **Microphone:** valid for up to two minutes before use and claimable only once when the main process mints a Realtime client credential. Browser microphone permission is allowed only for the trusted renderer while an owner-bound microphone grant or explicitly started microphone-caption session remains active.
- **Screen reference:** valid for up to two minutes and consumed by one source-enumeration request. A token from another renderer, an expired token, or a reused token is rejected.

All grants are cleared when the application window is destroyed. Raw grant tokens are never a replacement for OS microphone permission or the user's responsibility to obtain required participant notice and consent.

## Bring your own key

Interview Studio has no login or signup system and bundles no shared vendor credential. Each user supplies an OpenAI API key associated with their own project.

Keys entered in Settings are encrypted with Electron `safeStorage` when the operating system exposes a supported credential store. If secure storage is unavailable, the app keeps the key in memory only for the current process. A manual key takes precedence over `OPENAI_API_KEY`; removing the manual key restores the environment value as the fallback without exposing either key to the renderer after submission.

The coaching model is selected independently from the credential. Settings offers a constrained list of recommended models. A syntactically valid `OPENAI_MODEL` supplied at launch takes precedence over the saved selection; this override is reported to the renderer as environment-managed but is not rewritten by the UI. Model availability and billing remain properties of the user's OpenAI project.

A future provider-funded service must not embed its shared secret in the desktop bundle. It would require an authenticated backend that issues short-lived credentials and enforces server-side rate, spend, and abuse controls.

## Proxy boundary

Proxy configuration exists for authorized network connectivity, such as a user-managed proxy or an organization-approved network route. It is not designed to conceal use of the application, evade monitoring, bypass proctoring or access controls, or provide anonymity.

The supported modes are:

- **System:** defer to the operating system's proxy configuration.
- **Direct:** explicitly connect without a proxy.
- **HTTP:** use a fixed HTTP proxy for OpenAI HTTPS requests. Chromium establishes HTTPS tunnels through the proxy and retains normal certificate verification.
- **SOCKS5:** use a fixed SOCKS5 proxy for supported TCP/HTTPS requests. Chromium does not support SOCKS5 username/password authentication, and the app rejects SOCKS5 credentials.

All OpenAI HTTPS requests made by the application—including coaching API calls, Realtime credential creation, and WebRTC SDP/signaling exchange—are issued through Electron's configured Chromium session. The app does not rely on Node's independent default `fetch` path for those requests. Proxy changes clear cached authentication and existing pooled connections so later requests use the selected route; changing the route can therefore interrupt work already in flight.

HTTP proxy credentials are handled only in the main process and are supplied only to a proxy-authentication challenge whose host and port match the active configured HTTP proxy. Credentials are never embedded in the proxy URL or added to OpenAI request headers. The password is never returned by the settings API; the username is returned so Settings can display and edit it. Saved proxy credentials are encrypted together with Electron `safeStorage`; when OS-backed secure storage is unavailable, they remain in process memory only and are cleared on exit. Non-secret proxy metadata such as mode, host, and port may be stored in the local settings file.

The connection test verifies that OpenAI HTTPS traffic is reachable through the resolved route without sending the user's API key. It must not be described as an anonymity, IP-leak, or complete-tunnel test.

### WebRTC limitation

Electron proxy settings govern HTTP/HTTPS URL loading and signaling, not every possible WebRTC transport. The legacy Realtime microphone client uses a peer connection whose media and data channel may negotiate direct ICE/UDP paths. The live-caption panel instead uploads bounded PCM WAV chunks over the selected caption provider's origin-restricted HTTPS transport, which follows the configured proxy route. Consequently, HTTP and SOCKS5 modes do **not** guarantee that live audio, WebRTC data, DNS activity outside URL loading, or every network packet is carried through the configured proxy. A strict all-media tunnel would require a different, explicitly proxy-aware media transport and is outside this setting's guarantee.

The application must not disable TLS certificate validation to accommodate a proxy. A network that performs TLS inspection must install and manage its certificate through the operating system's normal trust controls.

## Pseudonymous OpenAI safety identifier

When a Realtime credential is first requested, the main process creates a random installation ID and attempts to store it in the local application settings. It derives `SHA-256("interview-studio:" + installId)` and sends that pseudonymous value in the `OpenAI-Safety-Identifier` header when requesting Realtime client credentials.

The installation ID is not an Interview Studio account, email address, or user-selected identity. When local settings are writable, it persists across launches until application data is reset; otherwise the identifier is best-effort for that run. Its purpose is a consistent abuse-prevention signal and it must not be expanded into cross-service tracking.

## Session, capture, and export data

- Raw microphone audio is streamed to OpenAI for transcription and is not intentionally written to disk by the app.
- Proxy passwords follow the same OS-encrypted-or-memory-only rule as other local secrets. Proxy metadata and the selected coaching model may persist in the local settings file.
- Caption text, saved translations, questions, coaching output, caption context, and unsent text drafts persist as plaintext JSON in the user-data `conversations` folder. They are local history, not OS-encrypted secret storage. Audio, screenshot pixels, and API keys are excluded from this schema. Manage or delete individual conversations in Conversation history; HTTP cache recovery preserves them. Atomic replacement keeps the previous file if a write fails, and normal exit flushes pending text edits before closing. An abrupt process or OS failure can lose edits made since the last acknowledged save.
- Source selection and area capture require an explicit action and consume a one-time, owner-bound capture grant. There is no continuous screen capture.
- Area selection overlays can read only the snapshot associated with their own main frame in the active capture session. The main process validates normalized crop bounds against that snapshot; cancelling, timing out, losing the owner, or quitting destroys the overlays and releases their snapshots. Overlay pages cannot use the main window's privileged settings or coaching IPC.
- Unselected thumbnails are cleared when the picker closes. All selected screenshots are attached to one coaching request and then detached by the renderer. The main process validates each image and enforces a per-image size limit. Attachment count and combined payload size are not capped by the app; the selected provider may impose its own request limits.
- Coaching uses `store: false`, but OpenAI processing and retention are still governed by the user's project configuration and applicable provider terms.
- Export is an explicit declassification step: the native save dialog writes UTF-8 Markdown or text to the user-selected path. **The exported file is plaintext and is not encrypted by Interview Studio.** The user is responsible for its access controls, sharing, retention, and deletion.

The main process validates request shapes, length limits, supported image data URLs, export size and filename, and request rates. Transcript and screenshot text are labeled as untrusted model input.

## Product-integrity boundary

Live transcription and coaching are allowed only when the interviewer, platform, and applicable policy explicitly permit them. The app must remain visible and must not suppress its AI-assistance or microphone indicators.

Screen-share concealment, "undetectable" behavior, taskbar or window-list disguises, panic hiding, monitoring or proctoring bypasses, undisclosed recording, candidate impersonation, and use of proxy support to evade authorized controls are security and product-integrity regressions and are not accepted features.

The foreign-window stealth feature operates inside that boundary and mirrors the WinHider interaction model: it applies the capture exclusion and the taskbar/Alt-Tab hiding to the top-level window that has keyboard focus when the user presses the configurable global stealth hotkey (persisted in local settings), records the exact pre-change state (window style and display affinity), and restores it when the application exits cleanly; a second configurable hotkey restores every modified window at once. The capture exclusion must run inside the focused application's own process because Windows rejects `SetWindowDisplayAffinity` from any other process: Interview Studio writes a 26-byte stub into the target process and starts one remote thread that calls the API with the requested affinity and exits immediately. The injection is transient — no resident code, no installed files, no elevation; 32-bit and elevated targets are reported rather than forced; only the display-affinity flag and window style of the explicitly focused window are touched. Security software may flag remote-thread creation; when the helper cannot run, the feature reports the failure instead of trying other means. The disguises in the previous paragraph are regressions only when used to defeat monitoring or proctoring the user has agreed to; the explicit, restored, disclosed window-privacy actions described here are the accepted feature.

OpenRouter API keys are kept separately from OpenAI and NanoGPT keys, encrypted through `safeStorage` when available or held only in memory. Only key status is returned to the renderer. OpenRouter chat, company-analysis, and caption requests use its configured HTTPS origin through the selected proxy route, and redirects are rejected. The connection test validates the key using `/key` before reading `/models`. Questions, profile context, and explicitly attached screenshots are sent to OpenRouter and the selected upstream model provider. When OpenRouter captions are explicitly started, selected audio is also sent to OpenRouter and its transcription provider.

Chat HTTP and SSE errors retain only allowlisted codes, limit sources, retry timing, and a bounded affordable-token count; upstream error messages and metadata bodies are not forwarded to the renderer. An OpenRouter Q&A attempt can make one smaller-budget retry after an HTTP 402 rejection quoting an affordable output budget. Unknown limit sources, key caps, in-flight budgets, insufficient minimum budgets, and already-started streams are not retried this way. No credentials, spending limits, saved models, or preferred provider settings are changed.

Q&A credit/quota failures can restart the question on another configured provider. Main snapshots eligible saved credentials/models and bounded request context, never accepting a fallback destination or credential from a renderer event. Each provider is visited once, with at most four providers sharing the original deadline and cancellation signal. Ordinary authentication/model/network/throttling errors do not initiate this chain. Keyless LM Studio is eligible only when explicitly saved/configured, rather than merely present as a default. A fallback receives the same full question/profile/context/screenshots, so these can be sent to more than one configured provider. UI notices identify the actual provider; fallback never overwrites the preferred provider setting. If streaming had begun, the earlier partial is retained separately (at most three, bounded by the history schema) and excluded from subsequent answer context. OpenAI HTTP/SSE error data is normalized to safe codes; SDK automatic retries are disabled for Q&A so billing failures do not repeat on the same account. No keys, account spending limits or provider models are modified.

User-initiated answer retries use the same coaching IPC, trust checks, deadlines, and rate limits as new questions. Failed attempts cannot lock a caption selection into displaying an error forever. Error notices are stored separately from generated answer text and excluded from follow-up context; older history remains readable. Only the latest failed/stopped request can retain screenshots in renderer memory for an immediate retry. A successful answer, a replacement request, or a conversation switch releases that cache. Older screenshot questions require explicit reattachment instead of silently omitting image input.

Live-caption sessions are created only by the trusted main frame after the explicit Start action, expire after four hours, and authorize only the selected input sources. Computer-audio permission is a one-shot display-media grant for that owner; other frames, repeated grants, and cameras remain denied. The renderer immediately stops the required display-video track and processes only audio. Main-process transcription validates session ownership, source, monotonic sequence, timestamps, PCM size, and one in-flight request per source. The renderer stops on backlog instead of retaining an unbounded recording.

Caption provider selection is validated and persisted separately from the answer provider. Each caption run snapshots its connection and key; changing the caption provider stops the existing run. There is no automatic provider fallback. Upstream OpenRouter error bodies are not shown because they may echo sensitive input.

Offline captions use a separate Electron utility process for native sherpa-onnx inference, keeping CPU work and native failures outside the main/UI process. The local path has no transcription network calls and needs no key. PCM stays in memory; stopping terminates the inference process and rejects late results. The same session ownership, source, size, ordering, and backlog checks apply. Native inference has a bounded 120-second deadline; cloud transcription retains its 30-second deadline.

The offline path uses continuous 512 ms PCM batches and a persistent recognizer per selected source. Speaker segmentation and embedding models are not loaded; no voice references or identity bank are created. Developing caption groups replace prior revisions instead of appending duplicate transcript text. Pausing discards partial input batches; a timestamp gap flushes and replaces the old recognition stream on resume. Cloud caption uploads retain pause/12-second segmentation. Computer loopback disables microphone processing to preserve the played audio; this does not change microphone permissions.

Offline microphone output is checked against sustained speech timing from bundled libfvad/WebRTC WASM. Only short frames and bounded timing ranges are retained; the detector makes no identity claims, downloads no models, and uses no network. Computer audio recognition is not gated by it. Microphone mute disables that audio track, drops partial batches, and discards queued or late microphone results, while computer capture continues. Pause/Resume preserves mute. This is independent of source permission and does not request new device access.

Offline model setup is an explicit action. Only six fixed recognition, punctuation, and vocabulary URLs can be requested, with no API credentials or caller-supplied URLs. The two punctuation files come from a pinned individual-file mirror and were verified against the official sherpa-onnx English punctuation release. Downloads follow the configured proxy and upstream CDN redirects; exact expected sizes and pinned SHA-256 hashes are checked before files are atomically installed. Partial files are removed on failure/cancel, and complete verified files are retained for retry. The initial scan verifies all model files before granting offline readiness. Files are data only, with no archive extraction or downloaded executables. Models are stored outside the application bundle in its user-data directory; quitting cancels setup downloads. Offline captioning never automatically switches to a cloud provider on missing models or errors. Punctuation restoration runs inside the isolated inference process and can change casing and punctuation only; recognized words and timestamps are preserved.

Caption raw audio is memory-only. OpenAI and OpenRouter receive plain transcription requests without diarization, speaker references, or identity metadata. Stop revokes the session and aborts pending requests; the renderer stops media tracks and its audio graph. Caption and translation text persist in local conversation history. YOU/Professional labels come only from the microphone/computer capture source, including on library restore and export. Automated desktop checks use generated tones or explicit public speech fixtures; the real-video benchmark separately uses authorized computer-audio playback.

Long-interview memory indexes original caption text locally and selects bounded verbatim excerpts for an extractive summary and keyword retrieval. It does not call a summary API or index generated answers as candidate facts. Sending a question includes the selected overview and retrieved earlier speech from that same conversation in the configured chat request, within the existing 24,000-character history-context limit. Those exact excerpts are saved with the answer for inspection/export. Source labels, elapsed timestamps, and prompt instructions preserve their status as untrusted, potentially inaccurate recognition. A new conversation gets an empty index; reopening rebuilds the index from saved captions. Large conversations use five-second periodic save batches with immediate switch/exit flushing, so abrupt termination can lose the most recent unsaved batch.

An explicit per-passage translation retry uses a separate allowlisted IPC handler restricted to the trusted main frame. It accepts only bounded text, a fixed target-language identifier, and a request ID; the renderer supplies no provider, credentials, URL, or model path. This text-only action also works on saved captions without a live recording session. It shares the two-request concurrency and 120-starts-per-minute limits with live translation. One selected-provider attempt has a 20-second deadline, followed on failure by a 30-second offline attempt using a verified installed English-to-target pack. Incompatible non-Latin source scripts are rejected; this is not reliable source-language detection for Latin scripts. Downloads require a separate explicit click. Offline success retains its origin in history and export. Cancellation is owner-scoped; changing target, provider, or conversation discards late output, and a retry cannot overwrite an ASR revision that changed its source text. Both attempts failing produces a bounded per-passage message, preserving original speech and other translation jobs. Live skipped passages never invoke this fallback unless the user clicks their retry icon.

Caption translation is an opt-in text-only request through Azure Translator, Google Cloud Translation Basic, independently configured OpenAI/OpenRouter/NanoGPT models, or the selected chat connection including LM Studio. Independent model providers use separate translation keys and validated model identifiers; these never overwrite chat credentials or models. Dedicated translation keys are submitted through a separate trusted settings handler, validated, encrypted with Electron safeStorage, and omitted from public settings. Without secure storage, keys remain only in main-process memory; removing or replacing them never persists plaintext. Azure regions are restricted to region identifiers. Dedicated API requests use fixed HTTPS endpoint paths, credentials in headers, redirects disabled, and the app?s configured proxy transport. The optional connection test sends only a fixed short sample and is rate limited. Its renderer bridge accepts no credentials, model names, provider URLs, audio, or files; these come from main-process settings. Main validates the trusted frame, active caption session ownership, fixed language allowlist, request identifiers, and a 6,000-character input bound. It allows at most two requests at once, caps starts at 120 per minute, and aborts requests after 20 seconds. Stop, session replacement, navigation, provider changes, panic hide, and application exit cancel pending work. Translation responses cannot exceed 12,000 characters and are rendered as escaped React text. Provider error bodies are never forwarded. Caption passages are treated as untrusted text to translate, not instructions. OpenAI requests disable response storage. No automatic provider fallback occurs; a failed translation leaves original captions running. Translation text is saved in local conversation history, and enabling hosted translation is disclosed separately from offline audio capture.
